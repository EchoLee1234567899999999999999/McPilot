# 测试计划（Test Plan）

> 项目：McPilot · 麦门决策局 ｜ 版本：v0.3（Phase 3）
> 关联文档：[../docs/01-requirements.md](../docs/01-requirements.md)、[../docs/03-mcp-tools.md](../docs/03-mcp-tools.md)

## 1. 目标与范围

验证"门店 → 菜单 → 营养 → 券 → 价格 → 推荐"主链路在**正常与异常**条件下均行为正确、数据真实、绝不越权。

- **范围内**：6 个只读工具的调用正确性、参数规则、三策略打分、营养分层匹配、券时效/适用性、降级行为、性能与安全合规。
- **范围外**：下单/支付等写操作（本就不允许调用）。
- **当前状态（Phase 3）**：离线单元 **164 passed**、真实集成 **14 passed**；
  三策略与全部推荐场景均已覆盖（见第 4、5 节 T1~T18）。

## 2. 测试分层

| 层级 | 对象 | 手段 | 位置 |
|------|------|------|------|
| 单元测试 | `menu` / `nutrition` / `coupon` / `pricing` / `combos` / `recommender` / `pipeline` 逻辑 | 真实采集夹具 + 明确标注的测试替身 | `tests/unit/` |
| 集成测试 | `mcp_client` 与真实工具的调用链、**真实推荐** | **真实调用**（`MCPILOT_LIVE=1`） | `tests/integration/` |
| 安全测试 | 越权调用、凭据泄露 | 白名单断言 + 仓库扫描 | `tests/unit/test_safety.py` |

## 3. 测试环境

- Python 3.13（pytest）。
- MCP 通过 WorkBuddy 连接器接入；**测试中不落盘任何凭据**。
- 集成/端到端用例对"实时数据依赖"保持宽容：只断言**结构与规则**（如金额单位、字段存在、参数规则），不断言具体数值。
- 离线测试使用两类夹具：
  - `tests/fixtures/*.json` —— **真实采集**的 MCP 返回（券字段已脱敏）；
  - `tests/fixtures/coupons_applicable.synthetic.json` —— **明确标注 SYNTHETIC** 的合成券，
    仅用于验证"券适用并真实产生优惠"的代码路径。

## 4. 关键场景用例

### T1 — 正常查询（全链路成功）

| 项 | 内容 |
|----|------|
| 目的 | 验证理想输入下完整链路可用 |
| 前置 | 有可用门店、菜单、营养数据、可用券 |
| 步骤 | 给定"到店自取 + 城市/关键词 + 预算 30 + 热量 ≤600"，执行 FR-1~FR-6 |
| 预期 | 返回 Top-N 组合；每条含实付（元，2 位）、用券、营养、理由 |
| 通过标准 | 6 个工具均被正确调用；价格单位由分转元正确；推荐硬约束均满足 |

### T2 — 没有适用优惠券

| 项 | 内容 |
|----|------|
| 目的 | 验证无券时不阻断、不臆造 |
| 前置 | `query-store-coupons` 返回空或无可匹配券 |
| 步骤 | 正常执行至价格试算 |
| 预期 | 仍返回推荐；明确标注"当前门店无可用优惠券"；`discount=0` |
| 通过标准 | 不报错、不中断；推荐理由不含"已用券"等虚假陈述 |

### T3 — 预算不足

| 项 | 内容 |
|----|------|
| 目的 | 验证预算硬约束与友好降级 |
| 前置 | 最低可达组合实付 > 用户预算 |
| 步骤 | 预算设为明显偏低（如 10 元）执行推荐 |
| 预期 | 如实告知"预算不足"；给出最低可达价格与差距，或建议替代/减少项 |
| 通过标准 | 不返回超预算组合作为"推荐"；不编造更低价格 |

### T4 — 营养信息缺失

| 项 | 内容 |
|----|------|
| 目的 | 验证缺失数据不臆造、合理降权 |
| 前置 | 部分候选餐品在 `list-nutrition-foods` 中无匹配 |
| 步骤 | 营养优先策略下执行推荐 |
| 预期 | 缺失餐品标注"营养未知"；在营养策略中降权或排除并说明 |
| 通过标准 | 营养合计仅纳入已知项并注明口径；未知项**不得**按 0 或低热量处理 |

### T5 — 接口报错 / 超时 / 门店无效

| 项 | 内容 |
|----|------|
| 目的 | 验证健壮性与真实降级 |
| 前置 | 模拟：门店不存在、某工具超时、参数非法 |
| 步骤 | 分别触发上述异常 |
| 预期 | 重试后仍失败则如实告知；剔除失败项继续其余流程；不返回编造数据 |
| 通过标准 | 无未捕获异常；错误信息清晰；任何情况下都不伪造价格/营养/券 |

### T6 — 参数规则校验（回归）

| 项 | 内容 |
|----|------|
| 目的 | 防止传参规则错误 |
| 步骤 | 到店自取（beType=1）时校验**未传** `beCode`；得来速（beType=5）时校验**必传** `beCode`；非预约场景不传 `reservationDate` |
| 通过标准 | 与 [../docs/03-mcp-tools.md](../docs/03-mcp-tools.md) 第 2 节完全一致 |

### T7 — 安全合规

| 项 | 内容 |
|----|------|
| 目的 | 验证只读与凭据安全 |
| 步骤 | 静态扫描源码/日志/示例；运行期断言调用白名单 |
| 预期 | 不出现任何写操作工具调用；仓库/日志/示例中无 Token、`Authorization`、账号信息 |
| 通过标准 | 白名单外工具不可达；`.env` 被忽略；`.env.example` 值为空 |

## 6. 非功能测试

| 项 | 方法 | 标准 |
|----|------|------|
| 金额精度 | 以分整数计算 | 无浮点误差；展示保留 2 位 |
| 可解释性 | 检查每条推荐的 `reasons` | 每条 ≥1 条可追溯理由 |
| 可移植性 | 干净环境运行核心逻辑 | 核心零/极少第三方依赖 |
| 调用预算 | 统计 `stats.mcp_calls` | 固定 3 次只读查询；`calculate-price` ≤ `max_verify`（默认 12）；`query-meal-detail` ≤ `max_resolve`（默认 10） |
| 响应时间 | 计时（含外部调用） | 三档预算 ≈9~12 s；报告中如实标注；网络波动可接受 |
| 候选去重 | 相同购物车不重复试算 | 去重后唯一候选，避免重复 `calculate-price` |

## 8. 测试数据原则

**严禁使用伪造的价格/营养/优惠券作为预期值。** 单元测试通过**注入式测试替身**（明确标注为测试桩）验证逻辑；
集成/端到端只断言**结构与规则**，不断言具体业务数值。

- `tests/fixtures/` 为**真实采集快照**（券字段已脱敏）。
- `tests/fixtures/detail/` 为真实 `query-meal-detail` 的裁剪快照（仅保留结构字段，数值未改动）。
- 极少数用于驱动特定代码路径的合成夹具（如 `coupons_applicable.synthetic.json`）**明确标注 SYNTHETIC**，
  绝不冒充真实返回。
